# ClipSync for Android

Компаньон к ClipSync на ПК. Реализует протокол из `../PROTOCOL.md` —
сопряжение по QR и синк буфера по локальной сети.

## Важная оговорка — прочитать перед сборкой

Этот код написан и вычитан построчно, но **ни разу не скомпилирован** — в
среде, где он писался, физически нет Android SDK, а сеть до
`dl.google.com`/Maven Central не разрешена, то есть нельзя было ни
поставить инструменты, ни даже скачать зависимости. В отличие от ПК-части
(там хотя бы `cargo check` частично прогонялся), здесь единственная
проверка — внимательное чтение против официальной документации каждой
библиотеки. Откройте проект в Android Studio, дайте Gradle
синхронизироваться, и если что-то подсветится красным — это ожидаемо,
пришлите текст ошибки, поправим за один проход.

**Список мест, которые стоит проверить в первую очередь, если сборка не
пройдёт с первого раза** (от наиболее вероятного к наименее):

1. **Версии Gradle/AGP/Kotlin/KSP в `build.gradle.kts`** — самый частый
   источник проблем в любом Android-проекте. Android Studio обычно сама
   предлагает апгрейд при открытии — соглашайтесь. Если ругается конкретно
   на пару Kotlin/KSP версий — на странице релизов KSP на GitHub есть
   таблица соответствий.
2. **`PairingScreen.kt`** — стык CameraX + ML Kit + Compose, самое сложное
   место в проекте по количеству двигающихся частей.
3. **`Identity.kt`, метод `sharedSecret()`** — BouncyCastle'овский
   `X25519Agreement.calculateAgreement` в одних версиях пишет результат в
   переданный буфer (как здесь), в других может возвращать его напрямую —
   если не собирается, это первая правка.
4. Всё остальное — стандартные, много раз проверенные паттерны
   (Room, OkHttp, NanoHTTPD, Android Keystore) — тут риск минимальный.

## Сборка

1. Установите Android Studio (последнюю стабильную).
2. Откройте папку `android/` как проект — **не** папку `clipsync` целиком.
3. Дождитесь Gradle Sync (первый раз — долго, качает интернет).
4. Запускайте на реальном телефоне, а не эмуляторе — сопряжение и синк по
   локальной сети через эмулятор устроены сложнее (NAT сети эмулятора).
5. Телефон и ПК должны быть в одной Wi-Fi сети.

## Что реализовано

- Сканирование QR из настроек ПК → POST `/pair` → сохранение пары в Room.
- Приём `/push` с ПК через foreground-сервис (тип `connectedDevice`) —
  работает, даже если приложение свёрнуто; показывает уведомление с новым
  элементом.
- Отправка на ПК двумя путями: кнопка в приложении (когда оно открыто) и
  системное "Поделиться" из любого приложения (`ShareReceiverActivity`) —
  так, что для этого не нужно разрешение на чтение буфера в фоне, которого
  Android всё равно не даст с версии 10.
- Локальная история (Room) зашифрована отдельным AES-256-ключом,
  обёрнутым аппаратным ключом Android Keystore — тот же приём "конверта",
  что и AndroidKeyStore не умеет генерировать X25519-ключи напрямую на
  всех устройствах одинаково надёжно, поэтому raw-ключ генерируется в
  софте и хранится завёрнутым, а не самим Keystore-ключом.
- Перезапуск приёмного сервиса после перезагрузки телефона, если ПК уже
  сопряжён (`BootReceiver`).

## Чего нет

То же самое, что честно перечислено в основном `README.md` и
`PROTOCOL.md`: ретраев/очереди для офлайн-ПК, perfect forward secrecy,
настраиваемого порта. Плюс специфично для Android: UI не пытается
повторить прозрачность ПК-версии — это полноэкранное Material 3
приложение, а не плавающее окно, эстетика "стекла" тут неприменима так же
буквально.

## Разрешения — зачем каждое

| Разрешение | Зачем |
|---|---|
| `CAMERA` | сканировать QR при сопряжении |
| `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` | HTTP по локальной сети |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CONNECTED_DEVICE` | держать приёмник живым, пока телефон включён |
| `POST_NOTIFICATIONS` | уведомление о новом элементе с ПК (Android 13+) |
| `RECEIVE_BOOT_COMPLETED` | поднять приёмник после перезагрузки без открытия приложения |
